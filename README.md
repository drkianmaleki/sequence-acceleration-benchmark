# sequence-acceleration-benchmark

Benchmark code for the paper:

> Maleki, K. (2026). **Sequence Acceleration versus Trajectory Fitting for Early Learning-Curve Prediction: A Benchmark with Hidden Asymptotes and Trivial Baselines.** Submitted to *Applied Soft Computing*.

Given the validation-loss trajectory of a gradient-boosting run, predict the loss at a specified future round. The repository evaluates the accelerator roster — **52 sequence-acceleration methods from 12 families** (the count is `len(src.pipeline.ACCEL_METHODS)`; `python -c "from src.pipeline import ACCEL_METHODS; print(len(ACCEL_METHODS))"` prints `52`): Richardson extrapolation, Padé approximants, parametric curve fits, and the classical algebraic accelerators (Shanks, Wynn ε/ρ, Levin, Brezinski, Anderson) — **against five trivial comparators** (the last observed value among them; it is a comparator, not an accelerator), on **18 core and 6 held-out synthetic convergence regimes** with hidden, heterogeneous asymptotes, three noise levels, three gap-defined prediction horizons and 30 seeds (`python reproduce_all.py --plan`: 369,360 evaluations in the main benchmark; 2.85 M central evaluations across all phases, of which 257,040 are the Phase 0b order ladders, plus 6.1 M diagnostic calls), and re-evaluates six recorded real XGBoost curves (OpenML ids 1590, 1461, 1596, 23512, 41150, 41168) on a 90-cell (depth × target) grid.

This is **redesign v2** (2026-09). The design of the originally submitted version was rejected in review because (a) every regime shared one true asymptote L* = 0.01, (b) that exact value was handed to every method as the "assumed" asymptote, and (c) the headline horizons sat where the target had already converged, so a predictor that simply returned the constant beat every method. Each ingredient is removed here. The revision for *Applied Soft Computing* also removes every composite judgement from the evaluation (see *Descriptive reporting* below): failures are preserved rather than rescued, and every table shows the trade-offs directly. The numbers behind the paper are in `FACTS.md` and `paper_fragments/`, generated from `results/` by one script; the committed `FACTS.md`, `paper_fragments/` and `results/` are the output of the previous full run and are regenerated by the full run of this code.

## Design (redesign v2)

**Hidden heterogeneous asymptotes.** Each (regime, seed) draws its own true asymptote `L_true` log-uniformly from (0.005, 0.5) (`src/generators.py`, `config.ASYMPTOTE_MODE = "hetero"`). No method ever sees `L_true`; only the evaluation harness and the oracle comparator do (`tests/test_redesign.py` enforces the separation). The old shared-asymptote design survives only as `config.ASYMPTOTE_MODE = "legacy"` for the regression test that locks in the referee's finding.

**Assumed asymptote L̂ (`src/asymptote.py`).** What a method is told about the asymptote is a separate, explicit choice: `zero` (L̂ = 0, the deployment-honest default and the only mode of the main run), `half`, `oracle` (L̂ = L_true, labelled as such), `double`, and `winmin` (0.9 × the window minimum, data-driven). Every accelerator, feature extractor and cascade input reads `cfg["L_inf"] = L̂`; Phase 5b sweep 1 varies the mode.

**Trivial comparators and skill (`src/trivial.py`).** Five trivial predictors are registered as first-class methods: `constant_assumed` (returns L̂), `last_value`, `window_mean`, `window_min`, and the evaluation-only `constant_oracle` (returns `L_true`; flagged `is_oracle`, shown in tables, never ranked, never in a pool). Every record carries two kinds of skill. `skill = err(method) / err(best of the four deployable trivials on that cell)` is the **hindsight best-of-four (strict)** bar — the denominator needs the truth to pick the trivial, so skill < 1 means the method beat every non-oracle trivial predictor there, including the one only hindsight could have chosen; it is aggregated as `med_skill`. The **fixed-reference** columns `skill_vs_{assumed,last,wmean,wmin}` (error ratio against each deployable trivial separately) and `win_vs_{...}` (1 when the method's error is below that trivial's) are aggregated as `med_skill_vs_*` and `win_rate_vs_*` in every table that carries `med_skill` (Phase 1 aggregated / global / held-out, Phase 2, Phase 4 and 5a selector tables, real data v2).

**Gap-defined horizons with capping (`src/horizons.py`).** Horizons are defined by the remaining gap, not by index: for a target fraction g ∈ {0.5, 0.1, 0.02} (headline g = 0.1), `n_f(regime, n_obs, g)` is the first n > n_obs at which the noiseless gap to `L_true` has shrunk to g × gap(n_obs), searched forward and capped at 50,000. When the cap binds, the achieved fraction is recorded and the cell is **excluded from every pooled statistic**; capped cells are reported in their own `*_capped.csv` block (fragment `f11`).

**Core and held-out regimes (`src/generators.py`).** 18 core regimes (`single_exp` … `broken_power_law`) are used everywhere; 6 held-out regimes (`stretched_exp`, `logistic_tail`, `inv_sqrt_log`, `random_knots`, `real_boot_a`, `real_boot_b`) are evaluation-only: nothing is trained, tuned or derived on them, and every pooled table exists in a core and a held-out version. The two `real_boot` regimes are smoothing-spline lower envelopes of XGBoost validation curves trained on two OpenML datasets that are **not** in the recorded-curve test set — `electricity` (id 151) and `nomao` (id 1486), `src.datasets.REAL_BOOT_SOURCE_IDS` — built by `scripts/make_real_boot_sources.py` into `results/real_data/real_boot_sources.csv` under three pre-specified inclusion criteria (≥ 20,000 rows; envelope gap ratio gap(90)/gap(0) ≥ 0.05, i.e. still descending at the default observation depth; argmin round ≥ 150, i.e. still improving at round 150), with the measured values and verdicts in `real_boot_sources_provenance.json`. The six recorded curves of `real_data_curves.csv` are the real-data test set and are never used as a generator.

**Validity floor and ranking (`src/pipeline.py`).** Pooled tables are sorted by median error over uncapped cells; a method is rank-eligible only when its pooled valid rate is ≥ 0.9 (`config.RANK_MIN_VALID`) and it is not the oracle. Below-floor methods stay visible in an `*_unranked.csv` block with their valid rate. The same floor is the exclusion criterion of the artifact below.

**Excluded-method artifact (`src/dangerous.py`, `scripts/derive_dangerous.py`).** An accelerator is excluded from the ensembles when its pooled valid rate over the core regimes at the Phase-1 depth (uncapped cells, oracle excluded, pooled over the gap strata and noise levels with equal cell weights) is below `config.RANK_MIN_VALID` = 0.9, the same floor that governs rank eligibility. No composite score enters the criterion. The set is **re-derived from the Phase-1 output** into `results/phase1/dangerous_methods.json` (schema `dangerous_methods/v3`, which records the criterion and the floor); Phases 2–5 read that artifact and refuse to run without it. `dangerous` is the legacy implementation name for the exclusion condition; the paper calls it the excluded set. `config.LEGACY_DANGEROUS_METHODS` is kept only for the record; `scripts/check_dangerous.py` verifies that the artifact matches the committed Phase-1 table and declares the validity criterion.

**Descriptive reporting (`src/panels.py`).** No composite score is formed anywhere. Every set of records — one method on many cells, or one selector's choices — is summarised by one *descriptive panel*, implemented once (`error_panel`) and used by Phases 1, 2, 3 and 5b: `n_total`, `n_valid`, `valid_rate`, `cat_rate` over all records; `mean_error`, `sd_error`, `med_error`, `q25_error`, `q75_error`, `p90_error` over the valid records only, labelled *conditional on validity* wherever they are printed and always shown next to the validity rate; and `win_rate_vs_last`, the fraction of all records where the method is valid and its error is below the last-value error (an invalid record never wins). Phase 2 characterises `richardson_1` by its raw error and by its error normalised by the last-value error, `R_R = E_R / E_last` (`src.trivial.skill_score` rule: when `E_last ≤ 1e-12` the ratio is 1 if `E_R ≤ 1e-12` and +∞ otherwise; the pipeline counts how often that branch fired in `phase2_denominator_counts.csv`), and evaluates every candidate rule by what happened when it fired (`rule_panel`: the panels of `richardson_1` and of the routed method over the fired cells, the fraction of records and of cells where the routed method's error was lower, the median relative change, and the same panels over the not-fired cells). Phase 3 scores a selector on every record of every cell it chose a method for; an invalid choice stays invalid (no fallback), and a warning is printed when the validity rate differs between selectors by more than 0.001 at any horizon. The cascades' thresholds are fixed constants, so there is no cross-validation to run: the per-regime panel (`phase3_regime_results.csv`) is the per-family evidence, and the six held-out families of Phase 5a are the out-of-sample test (the former leave-one-regime-out step, whose folds could only reproduce those per-regime panels, was removed; its outputs remain at commit d6beb53). Phase 5b evaluates the cascade with the same `rule_panel`.

**Regime classifier (`phases/phase3.py`).** One row is the seed-averaged feature vector of one (regime, obs_idx, noise) cell, so seeds never straddle a fold boundary. Three protocols are reported side by side and never combined: `grouped_by_depth` (primary; `GroupKFold` with groups = obs_idx, so every fold holds out all cells at one observation depth and trains on the other depths — the same regime at adjacent depths remains in training, and the protocol tests transfer across depth), `grouped_by_noise` (check; groups = noise level) and `stratified_5fold_legacy` (comparison only; the easier random stratified split, where cells of the same regime at adjacent depths may fall on both sides). `phase3_regime_classifier.csv` repeats the split-unit sentence on every row.

**Order ladders (Phase 0b, `scripts/order_ladders.py`).** For every family with an order parameter — Shanks, Wynn ε and ρ, Levin t/u/v, Brezinski θ, Anderson, Neville, Padé, Richardson with free and with fixed exponents, and the parametric fits by number of terms — the *ladder* is the set of variants obtained by changing only that parameter in the family's own constructor in `src/accelerators.py`; the orders that are roster methods are the registry functions themselves (`METHODS[name]`), so nothing is re-implemented. Every variant, plus the trivial comparators, is evaluated on Phase 1's grid at the headline stratum g = 0.1 with exactly Phase 1's windows, noise streams, horizons and configuration (the loop mirrors `phases/phase1.py` line by line), and reported as descriptive panels per (family, variant, regime set) over the records of uncapped cells, noise levels pooled and per noise level (`results/phase0b/order_ladders_panels.csv`; fragments `f18`, `f19`). **Agreement check:** at the end the script compares every roster-marked variant's records with `results/phase1/phase1_records.csv` on `estimate`, `error`, `valid`, `catastrophic`, `n_f` and `capped` (exact equality, NaN == NaN), writes the verdict to `order_ladders_agreement.txt` and exits non-zero on any mismatch — a ladder is by construction the roster method's own Phase-1 result extended to the neighbouring orders. The variant count is derived from the ladder definitions (`python reproduce_all.py --plan` prints it).

**Paired perturbations (`src/diagnostics.py`).** The perturbation diagnostic of Phases 4 and 5a is paired per window: for one (regime, obs_idx, noise, seed) window of length n, one factor array F of shape (perturb_trials, n), F = 1 + perturb_scale · Z with Z ~ N(0, 1), is drawn once from `RandomState(perturbation_key(regime, seed, obs_idx, sigma))` (`perturbation_factors`), and every method at every horizon is applied to the same perturbed windows seq_win · F[t] (`perturb_iqr_with_factors`); `perturb_iqr` is the IQR of the valid perturbed estimates (NaN with fewer than two). A method's diagnostic therefore does not depend on which other methods are evaluated or on the order of regimes, and two methods on the same window are compared on identical perturbations. The shift diagnostic (`shift_iqr`, deterministic window shifts) is unchanged. Phase 4's rejection rules are the precision and recall of a detector of a pre-defined event — an invalid prediction or an error above `CAT_MULT` times the last-value error — and never involved a composite score.

**Provenance.** Every real-data summary row records the Phase-2 feature file that produced the regime centroids and the commit hash; the artifact records its source (repo-relative), commit and time; every fragment and every `FACTS.md` row names its source file, filter and formula.

## Reproducing all results

```bash
python reproduce_all.py --plan     # evaluation counts per phase (full and quick)
python reproduce_all.py            # full run: 4.4 h on 8 cores for the previous roster (measured 2026-09-21)
python reproduce_all.py --quick    # 2 seeds, 2 regimes per group, 2 noise levels: every phase end to end (~2-3 min)
python reproduce_all.py --skip-real-data
```

Order: Phase 0 → Phase 1 → Phase 0b (order ladders, ending with the agreement check against Phase 1) → exclusion re-derivation → Phases 2, 3, 4, 5a, 5b → real data → paper tables (`scripts/make_paper_tables.py`) → L_true terciles (`scripts/analyze_by_ltrue.py`, last because it replaces its own section of `FACTS.md`). Phase 5a evaluates its (depth × noise) blocks and Phase 0b its regimes in `cpu_count() − 1` worker processes; the output is byte-identical for any job count (`--jobs N`). Wall times of the previous full run: Phase 1 31 min, Phase 2 16 min, Phase 4 30 min, Phase 5a 2.5 h (7 workers), Phase 5b 38 min (with the since-removed CAT_MULT sweep), everything else seconds; Phase 0b has not been in a full run yet (about 8 min at 7 workers, projected from the quick run).

`results/` is committed with the output of the previous full run (code 842ddb9, log in `reports/logs/REPORT_5B_full_run.txt`), minus the outputs of removed code paths (the Phase 5b sweep 3, available at commit 842ddb9; the Phase 3 leave-one-regime-out files, the stability-score figure and the Phase 2 phase-diagram files, available at commit d6beb53) and plus the new `real_boot` source files; the full run of this code regenerates it, including the new `phase0b/` folder. Five per-record files (`phase1_records.csv`, `phase0b/order_ladders_records.csv`, `phase2_records.csv`, `phase4_raw.csv`, `phase5a_raw.csv`) are git-ignored and regenerated by the run. After a re-run, `python scripts/check_dangerous.py` confirms that the artifact still matches Phase 1 and declares the validity criterion. Don't mix output from different commits.

## Reproducing the paper tables

```bash
python scripts/make_paper_tables.py            # -> paper_fragments/*.tex + FACTS.md
python scripts/make_paper_tables.py --no-raw   # same, without reading the git-ignored raw files
python scripts/analyze_by_ltrue.py             # -> f13 (by L_true tercile), its FACTS section, results/phase1/phase1_by_Ltrue.csv
```

Both scripts are the last two steps of `reproduce_all.py`. The table script reads the per-stratum result files (never the legacy-named headline copies) and writes the booktabs `tabular` fragments to `paper_fragments/` (`f01` … `f20`; index in `paper_fragments/README.md`) plus `FACTS.md`, the list of every headline number with its file, filter and formula; `analyze_by_ltrue.py` needs the git-ignored `phase1_records.csv` and runs after it because it replaces its own section of `FACTS.md`. Fragment `f01_trivial_baseline.tex` — per stratum, core and held-out: the deployable trivials, the oracle reference, the rank-1 and median accelerator, with the per-cell win rate and median skill vs predict-L̂ and vs the last value as the primary columns and the hindsight best-of-four (strict) skill alongside — is the paper's first result. `f05` shows what happened when the Phase-2 cascade fired under each assumed-asymptote mode, `f05b` the sweep 1b (win rate vs the mode-invariant `last_value`; `constant_assumed`'s own error per mode is the value of knowing the floor), `f07`/`f08` report the real data three ways (all / pre-minimum / post-minimum targets), `f09a` the Phase-3 selectors' panels (conditional on validity; validity rate alongside), `f12` the validity by observation depth. The main-text tables of the revision are generated too: `f14` the fixed methods `rational_fit` and `richardson_1` next to the cascade on the real data, per dataset and pooled, pre- and post-minimum targets; `f15` the family bootstrap over the core regimes (§5.4: `BOOT_N` resamples of the regimes with `BOOT_SEED`, `rational_fit`'s win rate vs the last value and its cell-median error against each comparator, point and 2.5 / 97.5 percentiles); `f16` the generalisation summary (eligible accelerators per regime set, the Spearman ρ already behind the FACTS generalisation rows, the ranks of `rational_fit` and `log_linear`); `f18`/`f19` the Phase 0b order ladders (classical families; Richardson terms, fixed exponents and parametric models); `f20` the roster by family, derived from the registry. No table value in the paper is hand-typed.

## Tests

```bash
pip install pytest
pytest tests/          # 375 tests
```

`test_generators.py` checks the invariants each synthetic regime must satisfy (in particular that the noiseless generator output equals the truth function at every n; a mismatch there is silent at run time), that the `real_boot` sources are outside the recorded-curve test set and that their gap profiles are non-increasing envelopes from 0.7 to 0. `test_accelerators.py` verifies the accelerator roster on four analytic sequences with known limits, checks that the retired Weniger pair recovers a geometric limit, and asserts its identity with `levin_t1/t2`. `test_redesign.py` locks in the redesign: hidden heterogeneous asymptotes, the `L_true` / `L̂` separation (no method reads `cfg["L_true"]`), gap-defined horizons and capping, the trivial comparators and skill, the held-out split, the rank floor, and a regression test that reproduces the referee's finding under `ASYMPTOTE_MODE = "legacy"`. `test_pipeline_v2.py` covers the shared pipeline helpers, the explicit 52-name accelerator roster, the exclusion artifact (validity criterion, schema v3), the Phase-1 descriptive-panel schema, the Phase-2 records / targets / rules and Phase-3 selector panels, the Phase-5a serial-vs-parallel byte identity and the real-data provenance columns. `test_panels.py` checks the descriptive panel, the rule panel and the zero-denominator mask on hand-built records; `test_phase3_classifier.py` checks that the grouped protocols hold out whole depths or noise levels with every row tested once, classify a separable table perfectly and label every row with its split unit. `test_perturbations.py` checks the pairing of the perturbation diagnostic: the factors are deterministic and independent of call order and follow the documented key; removing a method from the Phase 5a block or reversing the regime order in Phases 4 and 5a leaves every `perturb_iqr` unchanged; two methods on the same window receive identical perturbed windows equal to the central window times F[t]; and `shift_iqr` is pinned. `test_order_ladders.py` checks the ladder sizes, that every roster-marked variant is the registry function itself and bitwise equal to it on random windows, that the ladder-only models run, that the ladder loop reproduces Phase 1's records exactly on a tiny grid, and that a corrupted reference is caught by the agreement check. `test_input_dependence.py` is the permanent guard against degenerate accelerators: on 96 generated windows every accelerator must react to a 1 % window perturbation on ≥ 90 % of the windows where it is finite and may coincide with a deployable trivial on ≤ 10 % of them; it also measures the L_hat-consumer list that Phase 5b sweep 1b evaluates. It was added after `weniger_d1/d2` were found to return 0 for every input (fixed in `src/accelerators.py::_weniger_delta`, forward-difference remainder `w_n = Δs_n` with Pochhammer weights); the corrected pair turned out to be numerically identical to `levin_t1/t2` (this codebase's Levin `t` uses the same forward-difference remainder, and the Pochhammer and power weights coincide for orders ≤ 2), so it was retired from the roster and `levin_t2` took its place in the Phase 2/3/4 pool (`src.pipeline.PHASE2_POOL`: eight accelerators plus `last_value` as the floor option).

## Where the numbers are

- `FACTS.md`: every headline number with file / filter / formula, grouped by topic (roster, trivial baseline, ranking, family bootstrap, skill summary, classical no-op, order ladders, generalisation, dangerous set, richardson_3 validity by depth, σ = 0 cancellation NaNs, invalid rates, capped cells, sweep 1, Richardson failure, selectors, ensembles, diagnostics, real data, real data fixed methods, L_true terciles, pipeline provenance).
- `paper_fragments/`: the tables, one file each (`paper_fragments/README.md` maps fragments to sources).
- `reports/REPORT_5B.md`: the report of the previous full run (wall times, evaluation counts, invalid rates per phase, the derived excluded set, the results inventory); `reports/REPORT_8A.md`: the code changes of this revision (roster, validity criterion, descriptive reporting, classifier protocols, `real_boot` sources) and their verification; `reports/REPORT_8B.md`: paired perturbations, Phase 0b, the removed leave-one-regime-out step, the generated main-text tables, and their verification; `reports/CROSSREF_8B.md`: the read-only Crossref check of the bibliography (proposed changes only).

## Data availability

- **Synthetic sequences** are generated deterministically from `src/generators.py` and `src/config.py`; no download is required.
- **Real XGBoost curves** were recorded from six [OpenML](https://www.openml.org) datasets (ids 1590, 1461, 1596, 23512, 41150, 41168) and are committed as `results/real_data/real_data_curves.csv`; the default real-data step re-evaluates these recorded curves without retraining, so it is exactly reproducible. `scripts/run_real_data.py --retrain` regenerates the curves (XGBoost-version drift in the third decimal is expected).
- **`real_boot` generator sources** are the validation curves of two further OpenML datasets, `electricity` (id 151) and `nomao` (id 1486), trained the same way and committed as `results/real_data/real_boot_sources.csv` with `real_boot_sources_provenance.json` (OpenML versions, library versions, seed, the three inclusion criteria with measured values); `scripts/make_real_boot_sources.py` regenerates them. They are generator inputs of the held-out `real_boot_a` / `real_boot_b` regimes and are never scored.
